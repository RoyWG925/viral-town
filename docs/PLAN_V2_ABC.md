## B. 動機 + 揭露 + 鎮民筆記（約 3 小時）
1. 回答格式加選填欄位 `motive`，值為 want / fear / bias / gossip / bottom / price / none，代表這次行動主要是被自己卡上哪一項推動。這屬於模型自己的認知，跟 thought 一樣。
2. `validate.ts` 保留 motive，值不合法時改成 none，**不會因此退回重答**（不增加延遲）。
3. `story.ts` 的 `revealOf(run)`：挑這局 log 裡真的出現、而且最有戲的一項（price > bottom > fear > want > bias > gossip）。小報角落寫「🔓 你發現了：阿德的價碼——被市長公開羞辱，就揭露欠款」。
4. 鎮民筆記：每人一頁，欄位預設「？？？」，被揭露過才解開（存在 localStorage，加 try/catch）。入口放在角色卡裡，例如「📓 你對阿德的了解 2/9」。
5. 測試
   - 揭露的那一項一定能在 log 裡找到對應的 decision。
   - 沒有 motive 的 log（舊錄影）不會揭露任何東西。

## C. 慶典八量表 + 20:00 結局（約 3 小時）
1. `engine.ts`：`world.readiness` 存放八個量表（人、物、錢、地、名、心、眾、時，起始值照設計稿）。只在已驗證事件發生時依規則表加減，每次變動都寫進該事件的 data，可以追溯原因。
2. 初版規則表，要用 P5–P11 的 log 離線校準，目標是「照常」「縮水」「延後」三種結局都會出現，而且沒有任何一種超過一半：
   - 舞台封鎖：地 −35、時 −25、人 −15、眾 −15
   - 親眼證實舞台有問題：地 −20
   - 美玲關店：物 −25（沒有花和鴿子）
   - 阿德關店：物 −20（沒有點心）
   - 預算或市長相關的爆料：錢 −25、名 −25、心 −20
   - 市長被迫聲明：名 −10
   - 攤商聚集：心 −15、物 −15（罷市）
   - 警察出動：眾 −15
   - 安全謠言傳到 6 人以上：眾 −20、心 −10
   - 志明貼出安撫公告：心 +10、眾 +10
3. 20:00 結局判定（市長取消優先）：
   - 地 < 30 且（人 < 30 或時 < 30）：延後。
   - 任一量表 < 30：縮水，並列出缺了什麼（沒有鴿子、沒有點心、市長缺席、人潮冷清……）。
   - 其他情況：照常。
4. 呈現
   - 遊玩中：不顯示數字，只有世界徵兆（鴿籠空了、人潮變稀、封鎖線）。
   - 結算與小報：用一段文字交代「今晚的燈籠節：……」，並註明「根據今晚發生的事」。
5. 測試
   - 量表只會因為已驗證事件而改變。
   - 同一份 log 永遠算出同一個結局。
   - 用 P5–P11 校準後，結局的分佈要印出來檢查。
